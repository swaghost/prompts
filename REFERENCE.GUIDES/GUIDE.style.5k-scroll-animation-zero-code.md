# Build a $5k Scroll Animation with Zero Code

## Description

A comprehensive guide for creating professional scroll-linked image sequence animations (the Apple product-page effect) using AI from start to finish—zero coding required. Generate start and end frames with AI, let AI fill in every frame in between, slice the clip into images, and hand the folder to an AI coding tool that wires it to your scroll. The same technique Apple uses on the AirPods page.

## Tools Required

- **Google Flow** (labs.google/flow) — AI image generation (formerly Whisk, merged into Flow in April 2026)
- **Veo Frames to Video** (in Flow) — Frame interpolation and animation
- **EZGIF** (ezgif.com/video-to-jpg) — Video-to-frame extraction
- **AI Coding Tool** — Claude Code, Antigravity, Cursor, or similar
- **GSAP + ScrollTrigger** — JavaScript animation library (auto-generated by AI coding tool)

## What You're Actually Building

A scroll-linked image sequence. Instead of a video that plays on its own, you have a stack of still frames painted onto a canvas, and the scroll position decides which frame shows. Scroll down, it steps forward. Scroll up, it steps back.

That is why it feels like you are physically controlling the animation, and it is the same trick behind those high-end product pages.

## The Four Steps

### Step 1 🎨 Generate two frames in Google Flow

Go to **labs.google/flow** and generate two images from a text prompt: a **start frame** (how the animation begins) and an **end frame** (how it ends).

**Critical:** Keep the subject, angle, and lighting consistent between them so only the thing you want to animate actually changes.

**Note:** Whisk shut down in April 2026 and merged into Flow, so do everything here.

### Step 2 🎬 Animate the in-between with Frames to Video

Still in Flow, choose **Frames to Video: First + last**, upload both images, add a short motion prompt (for example, "slow smooth 360 rotation"), and let Veo generate every frame between your start and end.

Download the clip.

### Step 3 ✂️ Slice the clip into frames in EZGIF

Go to **ezgif.com/video-to-jpg**, use **Video to JPG (image sequence)**, set it to **30fps**, convert, then click **Download frames as ZIP**.

Unzip it and you have a numbered folder of images, one per frame.

### Step 4 💻 Hand the folder to an AI coding tool

Drop the whole frame folder into an AI coding tool (Claude Code, Antigravity, Cursor, whatever you use) and paste the build prompt below.

It writes the code that links your scroll to the frames.

## The Two Image Prompts

**Step 1 lives or dies here, so don't freestyle it.** The trick: both prompts are word-for-word identical except the one thing that changes (assembled vs taken apart). That is what keeps the product, camera, and lighting matching across both frames, so the in-between animation stays clean.

### Start Frame (Your Product, Assembled)

**🖼 Generate this one first:**

```
High-end studio product photograph of [YOUR PRODUCT], fully assembled and intact, floating dead center against a seamless matte light-grey studio background. Straight-on view, perfectly level camera, soft even studio lighting, one subtle soft shadow directly beneath the product, photorealistic, ultra sharp, high detail. Keep the product small enough in frame that there is generous empty space on every side. No text, no watermark, no hands, no props, no brand logos. Landscape 16:9.
```

### End Frame (Your Product, Taken Apart)

**🧩 Same words, one thing changed:**

```
High-end studio product photograph of the same [YOUR PRODUCT] as a clean exploded view: the outer shell or casing lifted apart and every major part and layer separated and floating in an organized, evenly spaced arrangement along one axis, like a technical teardown render. Same straight-on view, same perfectly level camera, same soft even studio lighting, same seamless matte light-grey studio background, one subtle soft shadow beneath. The core body of the product stays in the exact center at the same size, with the parts spreading outward around it. Photorealistic, ultra sharp, high detail. No text, no watermark, no hands, no props, no brand logos. Landscape 16:9.
```

### What to Swap

Swap the bracket for anything: **a smartphone, a mechanical watch, a film camera, an espresso machine, a sneaker**.

**"Exploded view"** is the magic phrase—it is the technical name for those pulled-apart product renders, and image models know it well.

### Naming the Parts

For the end frame, name the **4 to 6 parts** you want visible:

- **For a phone:** battery, circuit board, camera module, speaker, tiny screws
- **For a sneaker:** outsole, midsole, insole, upper, laces
- **For an espresso machine:** boiler, portafilter, pump, casing panels

This prevents the model from inventing mush.

### Three Consistency Tips

1. **Generate the start frame first** and only move on once you love it
2. **If Flow lets you reference or reuse that first image** when generating the end frame, do that
3. **If the two frames come out looking like different products**, regenerate the end frame rather than fighting it in the video step—a retry here is cheap

## How to Get the Most Out of It

### 1 🎯 Lock your two frames before you animate

The whole effect lives or dies on the start and end images. Generate them with the same subject, camera angle, and background so only the motion changes.

**If frame one and frame two look like two different products, the in-between will look like mush.**

### 2 🐢 More frames means smoother, but heavier

**30fps on a 2 to 4 second clip is the sweet spot.** Longer or higher means a buttery animation but a heavier page, so if it feels slow to load, ask the coding tool to compress the images or drop to every second frame.

### 3 🪜 Brand new? Paste the build prompt exactly as-is

You do not need to understand the code. Drop the folder, paste the prompt, and ask the tool to **"run it and show me a preview"** so you can see it working before you touch anything.

### 4 🧠 Power user? Feed it your real page

Paste your existing site code or design system first, tell it your section width, fonts, and breakpoints, and have it match your stack (React, Webflow embed, plain HTML) instead of generating a generic file.

## The Honest Bit

This is genuinely how the pro version works, but **AI-generated frames can drift**—a logo warps, a reflection flickers, an edge wobbles.

**Solution:** Generate a couple of clips and pick the cleanest, and keep your animation short and simple (a rotation, an assembly, a single reveal) rather than a complex scene.

**Simple subjects on clean backgrounds give you the crispest result.**

## Troubleshooting

### Problem: Frames look inconsistent between start and end

**Solution:**

- Regenerate end frame using start frame as reference
- Check that prompt text is identical except for "exploded view" section
- Verify lighting and camera angle descriptions match exactly

### Problem: Animation looks choppy

**Solution:**

- Increase frame rate in EZGIF (try 45fps or 60fps)
- Extend clip duration in Veo (3-5 seconds instead of 2)
- Ask AI coding tool to "add frame interpolation for smoother scrolling"

### Problem: Page loads slowly

**Solution:**

- Ask coding tool to "compress images to 80% quality"
- Reduce frame count: "use every second frame instead of all frames"
- Add progressive loading: "preload first 10 frames, then load remaining frames in background"

### Problem: Animation doesn't work on mobile

**Solution:**

- Check that mega prompt includes "keep it sharp and centered on mobile"
- Ask coding tool: "optimize touch scrolling for mobile devices"
- Test on actual device, not just browser responsive mode

### Problem: Logo or text warps during animation

**Solution:**

- Avoid detailed text/logos in the animated area
- Add text overlays in post (after scroll animation generates)
- Use simpler products with minimal branding for cleanest results

## Advanced Techniques

### Multiple Animation Sequences

**Combine multiple product animations on one page:**

```
Build three scroll sequences stacked vertically: phone assembly (30 frames), watch mechanism (25 frames), and camera lens focus (20 frames). Each sequence should pin independently as it enters the viewport, play its animation, then unpin before the next sequence starts. Use GSAP ScrollTrigger for sequencing.
```

### Custom Easing

**Add motion feel to the scroll:**

```
Apply custom easing to the scroll animation: ease-in when scrolling starts, linear through the middle, ease-out at the end. Make it feel like the product has physical weight and momentum.
```

### Color Shift During Scroll

**Add color transitions:**

```
As the scroll animation plays, gradually shift the background from cool grey to warm beige. Time it so the color reaches peak warmth exactly when the product is fully exploded.
```

## Technical Details

### Frame Requirements

- **Format:** JPG (PNG works but creates larger files)
- **Resolution:** 1920×1080 minimum, 2560×1440 recommended
- **Frame Count:** 60-120 frames ideal (30fps × 2-4 seconds)
- **File Size:** Keep total folder under 5MB for fast loading

### Browser Compatibility

The GSAP + ScrollTrigger approach works in:

- Chrome 90+
- Firefox 88+
- Safari 14+
- Edge 90+

### Performance Optimization

**AI coding tool can optimize automatically:**

- Lazy load frames as user approaches section
- Use WebP format where supported
- Implement progressive enhancement fallbacks
- Add loading spinner during preload

## Final Tips

**The secret to scroll animations that look like $5k agency work:**

1. **Start with identical frames** — Same camera, same lighting, same background
2. **Name the parts explicitly** — Tell the AI exactly what should separate
3. **Keep it simple** — One clear motion (assembly, rotation, reveal) beats complex multi-step animations
4. **Clean backgrounds win** — Matte grey or white studio backgrounds give crispest results
5. **30fps sweet spot** — Smooth enough, light enough
6. **Test the frames first** — Preview the video before extracting frames
7. **Let AI do the code** — Don't write GSAP by hand, paste the mega prompt
8. **Optimize after it works** — Get it running first, then ask for compression/optimization
